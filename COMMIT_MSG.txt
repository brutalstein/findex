fix(ranking): camelCase query expansion for better recall, shared term splitter

- fts_query() and terms_to_fts_query() now share split_query_terms(), which
  expands camelCase/PascalCase identifiers into sub-words (e.g. "parseConfig"
  -> "parseconfig" + "parse" + "config"), improving recall for identifier
  queries without changing lexical ranking behavior.
- Identifier matching in Stage 1 of search_ranked_in_db now uses the original
  query (lowercased, alphanumeric-only) rather than expanded terms, so camelCase
  expansion doesn't corrupt exact-symbol lookups.
- Added regression test: rank_in_db_camelcase_query_matches_subword_definition
  verifies "parseConfig" matches a file defining parse_config_file.

199 tests pass, clippy -D warnings clean, cargo fmt clean, release build
and dogfooding pass.
