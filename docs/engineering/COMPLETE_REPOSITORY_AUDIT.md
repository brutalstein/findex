# Complete repository audit

Audited baseline: `247576e49eb5d42999d30dbce55c78e28c9e6397` (main). Branch of
this work: `enterprise/p0-safety`. The per-file table (path, kind, size,
SHA-256, lines, tests, local dependencies, purpose) is generated by
`validation/harness/file_inventory.py` into
[FILE_AUDIT.md](../../validation/campaigns/enterprise/FILE_AUDIT.md); archived
results are hashed in `validation/campaigns/enterprise/baseline_manifest.json`.

Scope actually read: every Rust source file in `crates/` in full (core, index
lib/context/refresh/symbols, watch, mcp, relations lib, cli launcher path; the
syntax extractor and the SCIP/LSP importers by function outline plus their
limits and tests), every validation script that can start a process
(`run-*.ps1`, `claude_*.py`, `common.py`), CI, README, SECURITY, architecture
and roadmap. Archived results were not re-executed: their recorded checksums
were verified (67/67 match, 4 runs; the vNext runs have no checksum file, so
their HEAD blobs are hashed in the manifest instead).

The order deviates from the brief in one point: the P0 live-model gate
(`622f044`) was implemented before this document was written, because the
brief makes it a precondition for every other experiment.

## Subsystem review

### findex-core
Project identity is the nearest ancestor with `.git` (file or directory, so
worktrees work). Index keys are rebuilt from `Component::Normal` parts only
(rejects `..`, roots, prefixes). Storage: `%LOCALAPPDATA%\Findex\indexes\<blake3(project path)>`.
Admission limits: 512 KiB per file, 100,000 files per sync (exceeding it
cancels the transaction instead of deleting unseen rows). Sensitive names:
`.env*`, key/cert extensions, `id_rsa`, `credentials.json`, `secrets.json`.
Redaction is a pattern list applied to model-visible text only; the database
stores raw source (A4, THREAT_MODEL).

### findex-index
Schema v3 (`PRAGMA user_version`): `files(id, path, hash, size)`, FTS5
`docs(path UNINDEXED, body, terms)` keyed by `files.id`, symbol tables keyed by
content hash + extractor revision. Reconciliation is one deferred transaction
retried on `SQLITE_BUSY`; corrupt databases are deleted (with `-wal/-shm`) and
rebuilt. Every returned hit re-reads the file and checks its BLAKE3 hash, so a
missed watcher event can cause a false negative but not stale evidence. The
context engine (`context.rs`) is described in CONTEXT_ENGINE_RESULTS; its
intent router, comment rule and budget are the weak points (A1–A3, A8).

### findex-relations
SCIP (bounded: 16 MiB input, 1,000 documents, 100,000 occurrences, 2 KiB
symbols) and captured-LSP imports, admitted only for files the scanner admitted
with the same hash. SCIP import replaces the snapshot in one IMMEDIATE
transaction (atomic generation); LSP captures merge per symbol and invalidate
edges of changed files. Impact is a bounded BFS over exact symbol IDs, depth 1
= "verified-semantic-reference", deeper = "potential". No typed edge kinds, no
schema version, not used by `findex_context` (A7).

### findex-watch
`notify` recommended watcher (ReadDirectoryChangesW). Bounded channel (2,048
events); overflow, create/rename/remove, ignore-file or `.git` changes, unknown
paths and a 120 s deadline force full reconciliation; plain modifications
refresh known paths. Any watcher error switches the session to full scans.

### findex-mcp
Newline-delimited JSON-RPC on stdio; frames over 1 MiB are discarded in
bounded chunks and answered with -32600; invalid JSON -32700; notifications get
no response. Versions: modern `2026-07-28` via `_meta` (unsupported → -32022
with the supported list) and legacy `2025-11-25`, `2025-06-18`, `2025-03-26`,
`2024-11-05` via `initialize`. Five tools; only `findex_context` is
`anthropic/alwaysLoad`. Logging goes to stderr. Requests are processed
sequentially; there is no cancellation support.

### findex-syntax
Tree-sitter definitions for Rust, Python, TypeScript/TSX/JavaScript and C++,
capped at 2,048 symbols per file and 512 KiB per source; syntax errors and
truncation are flagged, not hidden.

### findex-cli
`findex claude` launches the official native `claude.exe` found on PATH
outside the project, adds `--plugin-dir` when the bundled plugin is present,
refuses nested launches, and never reads Claude credentials. `doctor` reports
plugin/claude presence.

### validation/
Before `622f044` the default runner could start paid-subscription sessions
(A10). Truth sources: `git grep` (coverage, held-out callers), rust-analyzer
SCIP (call sites), fix commits of real issues (localization). The 642-query
golden set and the A/B task judges were written by the same author as the
engine (bias recorded in REMAINING_LIMITATIONS #1 and LIMITATIONS #8).

### CI and release
Windows-only CI with `--locked`, MSRV 1.85 job, RustSec `cargo audit`
(pinned 0.22.2), CycloneDX SBOM in the ZIP, SHA-256 file, build-provenance
attestation on non-PR runs, actions pinned by commit SHA. Binaries are not
Authenticode-signed (no certificate; not purchased). Builds are not shown to
be bit-for-bit reproducible.
